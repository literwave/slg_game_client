# 出生州中高级资源固定配置

出生州基础层只生成1～3级。旧版虽然固定了5/6级，但仍有135276块4级地连续成片，而且4级和高级资源同用开发建筑轮廓，因此仍显得扎堆。本版将4/5/6级全部纳入分散固定表，同时减少高级地数量、扩大间距。坐标表缺失、间距不足、坐标重复、占据阻挡或城市都会停止生成，不会自动补点。这里的“出生州”是静态州域分类，玩家出生位置由服务端决定。

## 权威配置

`tools/world/fixed-birth-resources.json`（schemaVersion=2）：逐项列出6069个固定点的ID、州域、(x,y)、资源类型、等级和分组。每个点能单独修改，重新构建不会重排。离线编排工具 `plan-dispersed-birth-resources.py --output <新候选文件>` 只输出待审候选表，拒绝覆盖任何现有文件，正式构建不调用它。本版已重新冻结坐标，后端应按导出快照的版本整体同步，不能混用旧版点位ID。

总量为5655块4级、366块5级、48块6级。每州每等级的木、铁、石、粮数量差不超过1；每州6级四类各2块。离线候选工具沿用固定表的各州5/6级资源配额，并按间距约束分散，不再依赖预设出生区数量。

任意4级以上地之间至少8格，任意5/6级之间至少28格，6级之间至少48格；本版实测分别为8.49、28.30、59.55格（欧氏距离）。出生州不存在相邻连片的4～6级地。

地图不再输出建议出生区或玩家容量。资源审计按真实 `regionRows` 检查各州等级、配比及成长梯度；玩家出生位置、周边供给评估和人口容量由服务端管理。

布局版本3保留以上出生州固定点，并将所有普通资源按类型和等级逐格混排。资源州和王畿的高级地也冻结为658个分散点；配比、间距、城池占地及石料协议接入见 `资源混排与协议接入.md`。后端获得的最终快照中所有格子都是确定的。

## 修改与导出

1. 修改固定坐标表中的具体条目。
2. 执行 `python tools/world/build-campaign-map.py` 更新客户端资源快照；如修改涉及地图图层，暂存TMX需由Creator AssetDB保存。
3. 执行 `python tools/tests/fixed-birth-resources-regression.py`、`python tools/world/audit-resource-progression.py`、`python tools/tests/campaign-map-regression.py`；修改山体编排时再执行 `python tools/tests/mountain-continuity-regression.py`。
4. 执行 `python tools/world/export-backend-map.py --output temp/world-map-export`，得到 `world-map-backend.zip`，同目录还有 `mapRes_0.lua`、`campaign-map.lua`、`terrain.lua`、`manifest.lua`。

包内是这四份 Lua：百万格资源与空地、山河阻挡与城市占地、州域关口与系统城池、SHA256 和地图版本。不包含玩家出生位置、`ResLand`、`ResLandType` 和固定点源表。导出器按客户端快照生成 Lua，并从压缩包重新读取校验，避免前后端各自生成不同地图。

服务端必须同步空地与阻挡分类，不能把类型0一律视为山河；坐标为0～999，格子ID是 `y * 1000 + x`。存档迁移、守军收益、占领与关隘权限仍由服务端执行。本轮不部署后端或改写玩家存档。
