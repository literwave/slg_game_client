# 千里山河 · 破关逐鹿

> 地形版本2已改为不规则山河与宽桥关城。本文的圆环范围和旧关口坐标为初版记录；当前数据约定、视觉与接口状态见 [自然山河地图](自然山河地图.md)。地图脚本不再生成或导出玩家出生位置，出生分配由服务端管理。

## 核心玩法

以同盟为单位，通过铺路、集结、攻关逐步进入更富饶的州域。地形提供明确的防线和战略目标，而不是把一百万格平均撒满高等级资源。

地图1000×1000格，坐标0～999；资源、地貌、关隘、城池与TMX逻辑图层使用同一坐标系与固定种子20261024。单格200×100像素，百万格资源用两份字节表存储，只缓存最多8192个近期访问的地块对象；节点仍按视口分批复用。

### 资源成长与出生区

出生州每48格设一个低级资源补给中心：中心半径5格以1～2级为主，12格内能找到3级，24格内有至少8块4级；木、铁、石、粮局部轮换。4～6级共6069个固定坐标：5655块4级、366块5级、48块6级。任意中高级点至少隔8格，5/6级之间至少隔28格，6级之间至少隔48格。取消连续4级带和出生点周围的8点高级地圆环；四类数量在各州、各等级内相差不超过1。完整规则、权威配置与后端导出方式见 `docs/出生州固定资源配置.md`。

资源州按距地图中心的距离渐进：外沿4～5级，中段5～6级，腹地6～7级，靠近王畿才少量出现8级。王畿外沿保留6～7级接续目标，9级集中在更深核心。高级资源采用6格大小的簇，形成联盟争夺热点。

`campaign-map.json` 仅提供静态州域、关隘和系统城池等地图数据，不再包含 `spawnZones`。玩家出生位置、容量和保护范围由服务端管理，客户端不会移动现有玩家主城。

检查命令：`python tools/world/audit-resource-progression.py`。实际表统计的三层平均等级约2.82、5.55、7.22；这是地图分布检查，不代表已验证服务器守军难度、收益数值或成长时长。

州界由两格厚山脉或水系隔离，八方向都无法在普通地面上绕过边界。18个指定通道是州域间的连接点：6个5级出关口、3个8级王畿关口、6个4级外围侧翼隘口、3个6级内圈渡口/关口。侧翼路线使被主关卡住的同盟仍可通过外交或迂回寻找另一条进攻线。

城市占地按等级预留3×3、5×5、7×7格，避免资源建筑穿进城池。关口沿用现有系统要塞类型50，城池沿用类型51，不虚构服务端尚未支持的新建筑协议。

## 通关规则（客户端已接入）

1. 以玩家主城所在州为起点；主城州的普通发展不需要关隘权限。
2. 己方或同盟控制的关隘连通其两端州域；同盟关系与关隘归属来自服务端数据。
3. 可以从已打通州域攻击相邻关隘；攻下前不允许向关后州域发起攻击、驻军、屯田或调动。
4. 任意一条完整的己方/同盟关隘链即可打通目的地；失去关隘后重新计算，存在替代路线时仍可通行。
5. 撤退、待命和征兵不被关隘拦截，避免失关导致部队无法撤回。
6. 攻关仍需满足现有接壤占领与服务器战斗条件；客户端不会自行授予领地或伪造战斗结果。

客户端通过现有区域扫描协议获取关隘归属，每30秒排入远处关隘所在区域，并在实际出兵前再次检查本地已同步的通关状态。空区域快照会清理旧归属，避免已经失去的关隘被永久视为己方。

## 推荐赛季规则（设计方案，尚需服务端实现）

- 第1～2天：新手保护与出生州发展，主关守军不可挑战；允许组建同盟、铺路和侦察。
- 第3天：开放5级出关口，开始资源州争夺；侧翼关口提供较低门槛的绕行路线。
- 第5天：开放8级王畿关口，推动大盟会战。关隘需要先击败守军，再由攻城部队削减耐久；耐久归零才转换归属。
- 补给建议：连续控制的关隘链决定前线补给；断路暂停前线补给加成，但不强制删除已占领土地，也不阻止撤退。
- 胜利建议：同盟占领洛阳并连续守住24小时，且至少保有一个通往王畿的己方关口，取得阶段胜利；奖励按战功、攻城贡献与驻防贡献分配。
- 上述开放时间、守军、耐久、补给、胜利和奖励均不在客户端本地结算。本次仅提供分级布局、出关限制、情报展示与定位入口。

## 界面（已落地）

### 连续缩放与地图层级

参考《全面战争》官方战役操作教程中的“滚轮拉远进入战略地图”交互：<https://academy.totalwar.com/campaign-keyboard-and-mouse-controls/>。

- 近景（相机半高约240～750）：资源建筑、部队与土地操作。
- 中景（约750～3200）：山河、关隘和城池，隐藏逐格资源建筑与资源色标。
- 远景（超过3200进入，低于2800退出）：停用逐格区域扫描与近景节点，显示固定2500块州域色面、州名、18个关隘、10座城池和主城标记。文字保持屏幕字号并避让，归属定期更新。
- 最大缩放按真实地图尺寸和窗口比例计算，能容纳1000×1000全图并预留16%边距；接近全图档时逐渐居中，普通缩放保持鼠标指向位置。
- 战略远景点击地图会定位该处并分级拉近；拖动、滚轮方向和小幅触控板滚动保留。
- 关口中心收窄为一个逻辑格，两侧保留连续山脊；仅封闭关门格就能隔断八方向通行。测试同时确认关门两侧连到指定州域，避免“关门断开但通路本来就不通”的假通过。

- 地块选中采用金色双菱形线、半透明底色和透明度呼吸；建筑不跟随选中放大。四类单格资源图改为中心锚点、按图片完整宽高适配菱形，保证四角都在边界内，不裁切树冠；多格城池与关隘保留独立尺寸。
- 信息卡使用系统字体，移除旧位图字体与残留装饰，正文按行高排版。卡片根据建筑高度优先放在上方，空间不足时改到左右或下方，并限制在可视范围。
- 已移除独立“天下形势”入口、弹窗和组件。全图观察统一通过地图连续缩放完成，关隘详情沿用地图选中信息卡。
- 普通地图不常驻资源等级文字、色块、城池/关隘名称，也不叠加外围资源拼图。资源沿用自然资源/开发建筑两类轮廓与尺寸变化，准确等级、产量和状态统一放到选中信息卡；战略远景保留必要的州域与地标信息。
- 约60%的可通行地表为空地。`mapRes_0.json.emptyCells` 明确区分可通行空地与同为类型0的山河阻挡，客户端用字节掩码读取，空地可选中，显示“无资源产出/可通行”。服务器必须同步此索引及占领规则，不能仅按类型0判定阻挡；客户端不会伪造服务器占领成功。
- 资源稀疏化后按真实州域检查等级配比、资源间距与成长梯度，不再按预设出生位置验证供给。
- 山体按实际PNG透明轮廓衔接，低矮山脚连续覆盖，少量主峰随山脊起伏；两侧山体向关口逐渐收窄，入口保持可见和可点击。所有非关口连接采样点均验证图片覆盖，18个关口验证不被山体或点击轮廓遮挡。山体按空间桶与视口复用，不因全图山体增加而逐帧全表遍历。
- 山脉使用连续岩质底色与密集重叠山体。点击山体可见轮廓时按实际山体底座定位阻挡，避免穿透选到后方地块；点击阻挡地面显示红色菱形与“请从关隘/渡口通过”，约1.8秒后消失，移动地图或选择其他目标会清除提示。

## 服务端接入与存档迁移

本仓库为客户端，**尚未修改或验证服务端地图、战斗与赛季逻辑**。联网发布前必须完成：

1. 服务端同步 `assets/resources/config/mapRes_0.json` 的一百万格资源表，以及 `assets/resources/world/campaign-map.json` 的关口和州域定义；格子ID使用 `x + y * 1000`。
2. 服务端地图边界改为0～999，读取山脉/水系和城池占地；新建角色的出生位置由服务端自身逻辑决定，不从客户端地图包读取。
3. 旧200格地图的存档必须根据(x,y)重新计算格子ID，并决定主城、领地、行军、标记与系统城池的迁移/重置策略，不能直接混用旧ID。客户端保留收到的玩家坐标，不擅自改写存档。
4. 在出兵与迁城等服务器入口执行相同关隘链校验，防止绕过客户端；扫描与推送要返回关隘最新归属，拒绝失效的出兵请求。
5. 服务端实现关隘耐久、守军、集结、开放时间、断粮和赛季奖励规则后，再完成联网攻关验收。
