# 迁城协议接入

入口：选择地图空地 → 迁城 → 确认目标坐标。资源地、现有城池和建筑不展示迁城入口；确认前再次检查目标是否为空地，以及当前已打通的州路线。

| 协议 | 客户端处理 |
| --- | --- |
| `User.c2s_move_city` | 使用当前 `net_pb` 编号和 protobuf 编码，发送 `{ pos: { x, y } }`。 |
| `User.s2c_move_city` | 接收 `cityPos`，同步角色主城坐标，通知地图城池缓存和 AOI，然后定位主城。 |
| `User.s2c_sync_city_pos` | 共用主城坐标同步；即使推送先于迁城确认，也只提示、定位一次。 |
| `Item.s2c_sync_item_data` | 继续沿用已有物品同步；迁城请求和确认都不在本地扣除迁城令。 |

坐标为 1000×1000 地图的整数格坐标，范围 0–999。消耗道具为协议注明的 `Item.Id=1001`；已同步且不足时提示迁城令不足，未同步的数量不当作零。最终占地和费用校验由服务端处理。

每次只允许一个迁城请求。8 秒超时释放请求锁并提示，不自动重新发送。匹配本次目标的迟到确认仍可同步；开始新目标后，旧目标确认不能解锁新请求。断线、退出登录时清理请求和定时器，旧确认不重放。普通主城坐标推送不强制移动玩家正在查看的镜头。

离线验证包括真实 protobuf 编解码、ACK/推送先后顺序、重复回包、合法边界与非法坐标、道具不足、超时、断线、选地确认/取消、占用变化重查，以及既有城池缓存旧占地清理。迁城相关检查通过，TypeScript 对比未新增诊断。

现有完整协议回归还有活动兑换旧用例失败；内城/资源栏回归仍期待另一版入口与初始化函数。本次未修改活动逻辑或改写这些用例来隐藏失败。

Manual Check：服务器上线后验证迁城令实际消耗、目标 3×3 占地限制、跨州迁城限制、AOI 实体推送及迁城后的地图画面。本次未启动或重启项目。

此前的左侧任务卡也已补回 HUD 挂接：完成后点击直接请求领奖，服务端确认后等待并显示下一项任务；「全部」打开任务列表。
