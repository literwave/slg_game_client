# 山口入口的自然衔接

问题来自两侧攻城入口复用城内地基标记：山体按整格 discard，连续地表又被整格替换为草色，出现显眼的菱形切口。并非关楼贴图尺寸或 Z 排序造成。

实机检查发现，仅将整格裁切改成圆形渐变，仍会在城门两侧留下两块不自然的草斑。入口需要沿城门方向衔接，而非围绕入口格中心清出圆孔。

WorldLandscape 的地形纹理 B 通道使用 255 表示城市地基，64/96/128/160 分别表示朝 X+/X-/Y+/Y- 的山口入口。城市地基仍精确裁切。山口内侧接到门槛，通道两边保留山脚，外侧逐渐恢复山体；渐变稳定在地图坐标上。连续地表仅在通道范围混入少量土色，入口格外保持原样。

该调整仅改变呈现。攻城入口、阻挡、可走格、桥梁水面、资源分布均未修改；入口继续保持完整点击面积。AOI 刷新、城市迁入迁出和重新进图均保留正确的裁切类型。

验证：

- Creator 3.8.8 已导入修改后的 EffectAsset，未标记 invalid。
- city-ground-landscape.cjs 在 200×100、200×125 两种格子比例通过：软裁切标记、入口点击、AOI 幂等、城市占用、迁出及重新进图恢复。
- pass-entrance-masks.cjs 使用真实配置检查 12 座山口、24 个入口、四个方向、桥头排除和原始阻挡/点击范围。
- pass-entrance-shader.cjs 从 Creator 的真实导入产物生成离线 GPU 测试。WebGL 1/2 三个材质通道全部编译；200×100、200×125 两种比例、四种方向全部通过。每种方向有 10638–10760 个渐变像素，连续过渡处最大相邻 Alpha 差值不超过 21/255；入口外山体和地表保持完整，城内地基仍独立处理。
- render-pass-entrance-review.cjs 使用项目山体、关隘和导入后的材质，生成潼关两侧入口的离线对比。检查内侧接门、外侧淡出与两侧山脚。
- 脚本刷新已完成。全项目 TypeScript 检查仍为 214 项已有用户代码诊断；WorldLandscape.ts、CityGround.ts 均为 0 项。
- 本轮曾启动 Preview 观察圆形草斑版本，随后恢复原相机及编辑器状态。新的定向通道版本通过上述离线检查，尚未重新进游戏验证。

材质沿用 [Cocos Creator 3.8 官方透明混合配置](https://docs.cocos.com/creator/3.8/manual/en/shader/pass-parameter-list.html)，使用 src_alpha / one_minus_src_alpha。
