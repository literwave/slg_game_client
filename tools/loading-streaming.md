# 启动与登录后渐进加载

启动只读取 `world/boot-configs.json`、轻量地图几何、7 张基础地形及当前视野图片；隐藏功能预制体不再成为 HUD 的直接依赖。地图坐标、百万格逻辑索引和服务端同步仍完整保留，分块的是表现层。

地图图片使用四路优先队列，后台最多一路，每个后台任务结束后间隔 120 毫秒再处理下一项。拖图时暂缓后台任务，点击界面会提升对应加载请求的优先级。视野外一圈预取，闲置 30 秒或纹理估算超过 96 MiB 后回收；活动节点和基础地形保持引用。节点复用时核验图片绑定，迟到的加载结果不能覆盖新地块。

登录进入可操作的地图后等待 1.5 秒，自动在后台准备全部功能预制体，以及武将、物品、技能和头像图片。常用窗口和武将首页先排队，剩余资源逐步补齐；不等待玩家打开界面，也不阻塞进图。编辑器/Game View 使用 UUID，正式构建使用 `ui-panels` Bundle。

预载只准备资源，不提前创建隐藏窗口，也不触发界面业务请求。功能预制体保留到地图会话结束；闲置 30 秒只销毁已经创建但关闭的窗口节点。未完成预载时提前打开界面，仍会优先完成加载并给出短暂提示；取消后不会自动弹出。返回登录或销毁地图会取消尚未开始的后台任务，已经交给引擎的请求不强制中断。

## 更新生成数据

配置的编辑源仍是 `assets/resources/config`。启动文件中的地图把类型、等级和空地标志编码为每格两个字节，其他配置只合并，不改变内容。不要手工编辑生成文件。

同步 `game_common` 的脚本会自动重新生成。手工改配置、地图 TMX 或地图图片尺寸后运行：

```powershell
./tools/prepare-streaming-data.ps1
```

构建前检查生成数据是否与源文件一致：

```powershell
./tools/prepare-streaming-data.ps1 -Check
```

脚本使用 PATH 中的 Node.js 或当前运行的 Creator，也可传 `-RuntimePath` 指定。Node 环境可直接执行 `node tools/prepare-streaming-data.cjs --check`。

## 验证

`loading-streaming-regression.cjs` 验证请求优先级、缓存引用、取消与迟到回调、开发/构建两种加载入口，以及紧凑地图与原始百万格逐格一致。`loading-protocol-regression.cjs` 保留真实主城资料和首屏图片就绪后才撤掉加载遮罩的约束。

比较进图速度时使用同一设备、同一构建和同一种缓存条件。`[MapEntry]` 日志记录配置、首屏、完整进图耗时及地图图片计数；`textureBytes` 是按图片尺寸估算的 RGBA 字节数，不是整个进程或 GPU 的实测内存。
